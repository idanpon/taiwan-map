# Taiwan Map — инструкции для работы с проектом

## Общий контекст

- Перед началом задачи прочитай `docs/HANDOFF.md`, затем документацию нужного модуля. Текущие инструкции пользователя важнее этих правил. На этом Mac также учитывай `~/.codex/RTK.md`, если файл доступен.
- Не считай новый чат продолжением всей переписки: используй этот файл, handoff и актуальный код. После существенных изменений обновляй соответствующий документ и краткое состояние в handoff.
- Для реальных данных поездки читай актуальные API/экспорт, а не стартовый каталог, старые скриншоты или частные снимки. Пароли, токены, ключи и персональные экспорты не выводи в чат и не добавляй в Git.

## Архитектура и границы

- Frontend: обычные HTML/CSS/ES modules, GitHub Pages. Карта — прямой MapLibre GL JS 6.15.0: OpenFreeMap Bright / Fiord, локально заданный OSM raster fallback. Leaflet больше не используется.
- Backend: Node.js 24+, SQLite, существующая служба systemd на VPS. Перенос локальной папки не требует изменения VPS, DNS, прокси или базы.
- Сборка: `npm run build:pages` создаёт `dist/`; не редактируй `dist/` вручную. Публичные настройки — `pages.config.json`; секреты находятся отдельно.
- Используй текущую архитектуру, общие CSS-переменные и существующие Lucide-иконки. Не добавляй платные сервисы, второй движок карты или новые серверные компоненты без запроса пользователя.

## Продуктовые договорённости

- Admin и editor имеют одинаковые права внутри продукта; только admin управляет пользователями. Viewer читает частные данные, но не меняет данные поездки; собственные способы входа доступны в профиле.
- Анонимно доступны только публичные нескрытые места и их публичные сведения. Общие заметки, календарь, скрытые места, экспорт и управление требуют входа. Права проверяются сервером.
- Карта, статусы, заметки и календарь общие для участников. Названия/цвета/символы/прозрачность статусов пользовательские: не привязывай справку к фиксированным названиям.
- Три дополнительных ярлыка: photoSpot, limitedDates, reservation. Несколько выбранных ярлыков фильтруются по OR; разные группы фильтров — по AND. Ярлыков на маркерах нет. Завершившиеся события не скрываются автоматически.
- Календарь: месяц, неделя, день и список; виды записей task / decision / visit. Неделя начинается с понедельника. По умолчанию открывается текущий период. «Сегодня» и текущий период используют одинаковую срочность; просроченные выделяются сильнее.
- Альтернативы при решении можно скрыть или оставить, без удаления. Пересекающиеся решения учитываются до снятия вопросительного статуса. Связанные задачи сохраняются при удалении места; удалённые места автоматически не восстанавливаются.
- Автопереноса сроков, фоновых уведомлений и ИИ внутри сайта нет. Изменение рейса/маршрута обсуждается через чат с предложением связанных переносов до их применения; подробности — `docs/PLANNING_OPERATIONS.md`.
- Новые ключевые функции сопровождай обновлением справки. Проверяй мобильный и десктопный интерфейс визуально, обе темы, длинные строки, раскрытые фильтры и отсутствие горизонтального переполнения. Сохраняй несохранённый ввод и состояние карты.

## Работа и проверки

- Сначала проверь `git status`, актуальную ветку и изменения других чатов. Для параллельных правок кода используй отдельные ветки/worktree; не перезаписывай чужую работу и не удаляй чужие checkout.
- Зависимости закреплены в `package-lock.json`. Основные команды: `npm ci --ignore-scripts`, `npm test`, `npm run build:pages`. Нужен Node.js 24+ с node:sqlite; пути локального runtime описаны только в `.local/LOCAL_SETUP.md`.
- Запускай подходящие существующие проверки и сборку. Для небольших обратимых визуальных правок не добавляй тесты, повторяющие реализацию. Для UI делай браузерную проверку реальных страниц, а не только макета.
- Публикация frontend идёт через текущий GitHub workflow из main. Изменения backend публикуются отдельно; frontend-коммит сам по себе VPS не обновляет. Порядок — `docs/DEPLOYMENT.md` и профильные документы.
- Перед миграцией или массовой записью в production создай согласованный SQLite backup; проверяй версии, количество записей и сохранность пользовательских заметок. Не запускай старые deploy/import-скрипты из `.local/` без проверки актуального кода и запроса пользователя.

## Локальные материалы

`.local/` исключён из Git: там частные снимки, импорты, история проверок и макеты. Это архив и контекст, а не актуальная production-база. Его содержимое нельзя включать в `public/`, `dist/`, PR или общедоступные артефакты. Используй относительные пути к репозиторию, а не исторический путь чата.
