# Единые правила задач для ChatGPT и Codex

Статус: готово, MCP-сервер обновлён
Обновлено: 2026-11-10
Основание: компактное планирование и единые правила для плагина Taiwan Map и прямой работы через Codex.
Связанные документы: [операции плана](../docs/PLANNING_OPERATIONS.md), [планировщик](../docs/PLANNING.md), [плагин](../docs/CHATGPT_PLUGIN.md).

## Зачем и что меняется

Ассистенты читают один источник правил перед созданием, изменением и перепланированием задач. Правила связывают структуру плана с одним результатом на задачу, одной целевой датой по умолчанию и различием внутренних и внешних сроков. Данные текущей поездки и ручное управление остаются за рамками изменения.

## Поведение и приёмка

- Codex читает канонический файл по обязательной ссылке из `AGENTS.md`. ChatGPT получает его текст через инструкции инициализации MCP и в результате существующего `trip_read` вместе с текущей датой в действующем поясе поездки.
- Канонический файл определяет выбор типа, поиск дублей, назначение сроков и приоритетов, зависимости и завершение. `proposal_save` направляет клиента к свежему контексту для создания, редактирования и перепланирования.
- Одна календарная цель помещается в `date_end` без искусственного начала. Прежние однодневные записи и текущие формы поддерживаются. Точное внешнее ограничение с поясом сохраняется в описании, если структурированная дата уже занята внутренней целью.
- Названия инструментов, входные схемы, состояния, права, подтверждение и `completed_at` сохраняются. Подходящие сроки, смысловые дубли и необходимость интервала оценивает ассистент. Общая серверная валидация сохраняет структурные ограничения и совместимость с просроченными задачами и историческими событиями.

## Реализация

1. Добавить один модульный файл правил и ссылки из инструкций Codex и документации операций.
2. Прочитать файл на MCP-сервере, включить его в общий контекст, доставлять его в образе backend и дать короткое указание в описании существующих инструментов.
3. Проверить действующий MCP-контракт и однодневный дедлайн на существующих тестах, сверить документацию.

## Проверка и результат

Единый источник — [правила задач](../docs/PLANNING_RULES.md). Сверены ссылки
из `AGENTS.md`, документации и навыка плагина. Существующий тест MCP
подтвердил получение текста при инициализации и в ответе `trip_read`,
действующий пояс поездки, сохранение одной целевой даты без начала и
применение прежним контрактом. Прошли 38 проверок плагина и планировщика.

Сборка Docker не запускалась. В поставке образа указаны файл правил и
исключение для него из `.dockerignore`. Backend обновлён после проверенного
снимка SQLite, без миграции. Рабочий `trip_read` вернул правила, текущую дату
и пояс поездки. Данные поездки при выпуске не менялись.
