Следующий этап — подготовить проверяемый пакет перехода и восстановления.
Локальная демонстрация с отдельными синтетическими данными открыта.

Сохранить проверенную резервную копию для отката. Повторного разрешения на эти
действия не требуется; при ошибке проверки сначала устранить причину.

## Поведение и приёмка

- Единая команда репетиции принимает SQLite backup прежней модели либо
  проверяемый bundle с файлами. Источник остаётся неизменным; каталог результата
  новый, права на частные файлы ограничены. SQLite без файлов отклоняется,
  если в нём есть ready assets.
- Репетиция сохраняет исходную модель для восстановления, отдельно проверяет
  применение SQL без включения model3, затем явный идемпотентный переход.
  Прежние записи, заметки, версии, аккаунты, связи и история сохраняются.
- Для нового результата создаётся полный backup, затем он восстанавливается
  в ещё один каталог. Сравниваются данные и все ready файлы, включая историю
  и личные загрузки. Незавершённые uploads истекают, storage leases очищаются
  по существующим правилам restore; это единственные допустимые различия.
- Отчёт содержит результаты и числа, не тексты поездки и не секреты.
  Незавершённый результат явно помечен. Команда не переключает сервер и
  не выдаёт синтетическую проверку за репетицию production.
- Проверить последовательность совместимости: новый API с model2, старое
  представление после перехода, запрет старых структурных writers и права.
  Зафиксировать порядок backend → Pages → явное включение модели и границы
  отката без потери принятых после перехода изменений.
- Проверка опубликованного Pages artifact должна охватывать новые модули
  маршрута и общие зависимости автоматически, без прежнего короткого списка.

## План

1. Открыть локальный стенд, сверить ветку с main.
2. Объединить существующие rehearsal и backup/restore в одну команду;
   добавить проверки отказов, сохранности и совместимости.
3. Прогнать репетиции на заполненных синтетических model2/model3, выполнить
   относящиеся к выпуску проверки и обновить эксплуатационные документы.

## Результат

Свежий согласованный backup с VPS и общая репетиция успешны.
Сохранены прежние поля, версии, заметки, история и напоминания; SQL оставляет
model2 до явного перехода, повтор перехода идемпотентен, FK/integrity и полное
восстановление успешны. Исходник не изменился. Файлов в прежней модели нет.
Частные копии, actor и журналы остаются вне Git/Pages.
Выполнен порядок: исходная копия → репетиция → backend с model2 → Pages →
остановка службы и финальная копия → повторная репетиция → model3 → smoke.
Ниже результаты предшествующей локальной подготовки и фактического выпуска.

Реализован `server/rehearse-planning-release.mjs`: один вход для SQLite/bundle,
исходная копия, переход, полный backup и проверенное восстановление. В прежний
rehearsal добавлен отдельный контроль применения SQL без включения model3.
Команды не запускают службу, не меняют production и не переключают пути базы.
Отчёт фиксирует версии SQL и policy; публикация остаётся отдельным действием.
