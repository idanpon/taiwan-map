# Фиксированные статусы, проживание и транспорт

Статус — готово. Backend и Pages опубликованы. Преобразование четырёх записей применено и проверено.
Обновлено — 2026-11-10
Основание — согласованное ТЗ Taiwan Map.
Модули — [статусы](../docs/STATUSES.md), [план](../docs/PLANNING.md), [карта](../docs/MAP_THEMES.md), [MCP](../docs/CHATGPT_PLUGIN.md).

## Поведение и приёмка

- Статусы мест ограничены `want`, `maybe`, `visited` и `null`. Последнее означает сохранённое место без решения о посещении. Действующие цвета, символы, прозрачность и назначения сохраняются. Каталог доступен для чтения, изменение его состава прекращается.
- `stay` представляет подтверждённую бронь с одним основным местом. Период ночёвок полуоткрытый, от заселения до выезда. Повестка и список включают оба дня, выводят проживание первым и показывают выезд → заселение при смене отеля. Ночь обозначается одним домиком даже при нескольких бронях. Отменённые записи не влияют на ночи и карту.
- `transport` представляет значимый переезд. Вид фиксированный, отправление и прибытие имеют названия, необязательные ссылки на карту, даты и собственные пояса. Точное время хранится в UTC, может быть указано отдельно для каждого конца. При отсутствии времени остаётся локальная дата. Остановки упорядочены, номер и сведения о терминале необязательны, билеты используют общие ссылки.
- Переезд виден с местными датами и часами обоих концов. В дневной хронологии точные события сравниваются по моменту соответствующего конца, записи без времени сохраняют ручной порядок.
- Задача бронирования остаётся `task` и связывается зависимостью. Самостоятельная активность остаётся `visit`. Используются текущие права, версии, история, правила напоминаний и предпросмотр MCP. Новые типы удаляются через API и подтверждённое предложение MCP с показом затронутых связей.

## Решения

- Храним общие поля в `planning_items`, параметры транспорта в типизированных при записи JSON-данных, основной отель и точки маршрута в общих связях с ролями. После удаления места его подпись остаётся. Для новых проживаний требуется существующий объект; историческая запись с удалённым объектом остаётся доступной.
- Тонкий контур сохраняет иконку категории. Признак проживания доступен участникам. Контур и компактные карточки согласованы 10 ноября. Пересекающиеся брони показываем вместе, одна иконка на ночь; блокировки или предупреждения пока не вводим.
- Совместимое чтение существующего API сохраняется. Полный список новых типов доступен с явным параметром модели и в MCP. Операции над существующими типами сохраняют семантику.
- Неизвестные значения дат/часов не угадываем. У транспорта локальная дата прибытия может быть раньше локальной даты вылета при корректном порядке по UTC.

## Реализация

1. Расширить ограничение типов SQLite, проверить все внешние ключи после переноса, архивировать только неиспользуемые кастомные статусы. Если обнаружено действующее назначение кастомного статуса, прервать миграцию до согласованного переназначения.
2. Расширить общую валидацию, API, экспорт, предложения MCP и единые правила ассистентов. Проверить повтор применения, ошибки версии, права и каскад зависимостей.
3. Добавить поля и компактные карточки в существующие виды, ночной индикатор и частный акцент карты. Проверить календарные границы, несколько броней, разные зоны, мобильные размеры и темы.
4. Отдельно от схемы подготовить адресный пакет преобразований из свежего API по ID и версии. Сохранить поля и зависимости. Проживание и однозначные рейсы переводим на месте; смешанные записи выносим на разбор. Применение общего пакета следует за SQLite backup, проверкой на копии и показом конкретного предпросмотра.

## Проверка и результат

- Пройдено 202 теста Node, в том числе обновление резервной SQLite с проверками
  целостности и внешних ключей, отказ при назначенном кастомном статусе,
  календарные границы, пояса и CRUD через HTTP и MCP. Сборка Pages прошла.
- В Chromium проверены реальные страницы на ширинах 320, 390, 1280 и 1440 px
  в обеих темах. Проверены формы, смена отеля, домик на границе месяцев,
  хронология, фильтры, контур жилья с сохранением значка статуса,
  публичная проекция и карточка предпросмотра. Использовалась тестовая подложка.
- Свежий авторизованный API не показал назначений кастомного статуса.
  Локально `0011` и адресный пакет прогнаны на данных, восстановленных из
  актуального ответа API. Архивировано одно определение. Четыре записи
  преобразованы на месте, общее число записей, заметки, даты, назначения
  статусов и связи сохранились. Смешанные переезды остаются посещениями по решению пользователя от 10 ноября.
- Backend и MCP выпущены 10 ноября после двух резервных копий SQLite на VPS.
  Репетиция `0011` на копии непосредственно перед переключением подтвердила
  целостность, внешние ключи и сохранность данных в 29 таблицах. После
  переключения сверены схема production и публичный каталог.
- [PR #58](https://github.com/idanpon/taiwan-map/pull/58) прошёл CI. На Pages
  проверены ревизия `57b663f` и хеши всех 13 файлов из манифеста выпуска.
- Подключённый MCP выдал свежий предпросмотр четырёх правок без предупреждений.
  Старая схема подключённого инструмента отклоняла новые типы при сохранении
  черновика. Черновик подготовлен штатным обработчиком сервера после проверки
  роли и активного разрешения.
  После подтверждения снята отдельная резервная копия SQLite с правами 0600.
  Прогон на копии воспроизвёл согласованный дифф и прошёл проверки целостности
  и внешних ключей. MCP применил подтверждённую ревизию. Квитанция и повторное
  чтение плана подтвердили четыре преобразования и сохранность ID, дат,
  заметок, зависимостей и привязок мест. Смешанные переезды остались
  посещениями. Пакет хранится вне Git.
- Проверка на физическом iPhone остаётся отдельной от браузерных проверок.
