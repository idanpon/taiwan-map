# Наполнение карты и плана через ChatGPT

Статус: готово (реализация локально; не опубликовано)
Обновлено: 2026-11-08
Основание: пользователь согласовал варианты 1А / 2Б / 3А / 4А и поручил сохранить спецификацию и начать реализацию. Telegram исключён из этапа.
Связанные документы: [архитектура](../docs/ARCHITECTURE.md), [операции плана](../docs/PLANNING_OPERATIONS.md), [план](../docs/PLANNING.md), [доступ](../docs/PUBLIC_ACCESS_PASSKEYS.md), [качество мест](../docs/PLACE_IMPORT.md).

## Цель и границы

Личный плагин позволяет из любого поддерживаемого чата ChatGPT с подключением к аккаунту карты подготовить и после подтверждения применить изменения. Архитектура поддерживает отдельные подключения других участников. Сервер определяет права по аккаунту карты; установка плагина в ChatGPT не заменяет авторизацию и не удостоверяет владельца аккаунта карты.

Разрешены добавление/редактирование мест, задач, посещений, решений и связей, статусы, переносы, скрытие/возврат мест. Окончательное удаление, управление пользователями, Telegram, самостоятельный ИИ на VPS и автоматический пересчёт сроков не входят в этот этап.

## Поведение

- Каждый чат читает актуальную поездку и связанные записи. Использует существующие категории/статусы, ищет дубли, учитывает связанные задачи и пересекающиеся решения. Новые сущности предлагает только с понятной причиной.
- Передаёт структурированные поля предложения, не всю переписку. Для места: названия, город, категория, адрес/координаты с точностью, описание, источники и проверка, необязательные часы/ярлыки/бронирование. Для плана: тип, даты/пояс, связи, зависимости, варианты, необязательный ответственный. Изменения содержат ID и версии записей.
- Описание и пользовательская заметка разделены. Неизвестные часы допустимы; непроверенная точка не выдаётся за точную. Неполное предложение можно явно сохранить личным черновиком. Другие участники его не читают; собственные чаты могут продолжить.
- Перед записью показать компактное «будет добавлено / изменено», видимость, затронутые связи, источники и неопределённости. Карточка предлагает применить, изменить, сохранить черновик и отменить. Даты, статус, видимость и состав пакета можно уточнить перед применением.
- Подтверждение кнопкой либо однозначным ответом в чате относится к конкретной ревизии предпросмотра. Неоднозначное «да» требует уточнения. Изменение пакета отменяет старый предпросмотр. Новые места по умолчанию публичные, план и заметки частные.
- Один подтверждённый пакет записывается одной транзакцией вместе с результатом операции и историей. Повтор с тем же идентификатором не создаёт дублей. После потери ответа сначала проверяется результат операции; временные ошибки допускают до трёх повторов с тем же идентификатором. Ошибки валидации/прав требуют исправления, конфликт версий — нового предпросмотра и подтверждения.
- Успех объявляется только по подтверждённому результату сервера. Пользователю доступны состояния «сохранено», «не сохранено», «результат пока не подтверждён». Закрытый чат не обязан автоматически возобновляться; результат можно проверить позже.
- Editor/admin равны при работе с поездкой, viewer читает без записи. Каждая операция подписана реальным автором; отзыв подключения/отключение участника немедленно прекращает доступ. MCP не открывает аккаунты, токены или личные уведомления других участников.

## Технические решения

- Существующие Node/SQLite и Pages, без отдельного ИИ API, очереди или базы.
- Общая служба предложений: личные черновики, ревизии, предпросмотр, атомарное применение и квитанция результата. Сохранение мест получает версию основных сведений; существующие версии статуса/ярлыков/видимости/плана сохраняются.
- MCP по HTTPS с ограниченными инструментами чтения, подготовки, предпросмотра, применения, проверки результата. OAuth authorization code + PKCE S256, отдельные ограниченные токены и отзыв; браузерная авторизация сайта не ослабляется.
- Серверный предпросмотр проверяет весь пакет через те же правила, что применение; существующая служба календаря переиспользуется. Подтверждение не позволяет произвольный SQL/HTTP/вызов административных операций.
- Пакет плагина содержит инструкцию поведения и MCP-конфигурацию. Карточка работает через MCP Apps; доступен авторизованный предпросмотр на сайте. Секреты и рабочие данные в пакет не входят.
- Сетевые источники считаются данными, не командами. Сервер не загружает произвольные URL, переданные моделью; факт проверки и точность выводятся честно.

## План

1. Миграция и общие операции мест/предложений; регрессионные проверки атомарности, повторов, конфликтов и приватности.
2. OAuth, MCP и браузерные маршруты с отдельной границей авторизации; проверка полного протокола и отказов.
3. Карточка, страница подключения/предпросмотра, пакет инструкции; проверка настоящих страниц на desktop/mobile и обеих темах.
4. Документация, справка, сборка и итоговая проверка. Выпуск backend с согласованным backup и подключение личного плагина — отдельный этап после готового проверяемого результата.

## Приёмка

- Место и связанная задача добавляются после подтверждения; необязательные часы могут отсутствовать. Черновик с неизвестными координатами не попадает на карту.
- Повторное применение и потерянный ответ не дублируют данные. Ошибка последней операции откатывает ранние операции и историю.
- Правка связанного объекта из другого чата/сайта блокирует устаревший пакет. Пользовательские заметки и закрытые решения не повреждаются.
- Viewer, другой автор черновика, отключённый участник, истёкший/отозванный токен не получают запрещённых действий/данных.
- OAuth проверяет точный redirect URI, PKCE, срок и одноразовость кода, scope и назначение токена. MCP отклоняет неизвестные инструменты, поля и превышенные размеры.
- Предпросмотр/подтверждение/результат работают на desktop/mobile, в светлой/тёмной темах, с длинными строками и без горизонтального переполнения.
- Подключение и выполнение из реального ChatGPT отдельно проверяются после публикации HTTPS endpoint; локальный протокольный тест не считается этой проверкой.

## Результат и следующий шаг

Спецификация зафиксирована до кода. В `codex/chatgpt-plugin` реализованы служба предложений, строгие схемы, миграция 0010, OAuth/PKCE, MCP, карточка, страница сайта, пакет плагина и инструкция поведения. Устройство и порядок подключения — [CHATGPT_PLUGIN.md](../docs/CHATGPT_PLUGIN.md).

Проверены транзакции/откат, повторы и квитанции, конфликты, сохранение заметок, решения, приватность/роли, OAuth и полный сценарий через официальный MCP-клиент. Общие проверки и сборка Pages выполнены. В локальном браузере проверены 375/1280 px, обе темы, длинные строки, изменение даты и повторное подтверждение, конфликт, сохранение/reload, OAuth-согласие; встроенная карточка — через официальный MCP Apps AppBridge. Инструкция прошла валидатор skill-creator.

Уточнения реализации: конфликт проверяется по снимку всей общей поездки (иногда новый предпросмотр нужен и после несвязанной правки); сложные связи и точное время редактируются в чате. Сервер проверяет реквизиты предпросмотра, но факт текстового согласия остаётся правилом доверенного клиента. Фоновых повторов после закрытия чата нет.

Production, реальные данные и ChatGPT-аккаунт не изменены. Возможность выключена по умолчанию. Следующий конкретный шаг после разрешения на выпуск: SQLite backup → проверка миграции на копии → обновление существующего API и Pages → личное MCP-подключение с точным callback/allowlist → проверка из двух настоящих чатов. Без зарегистрированного подключения нельзя заранее заполнить его внутренний `plugin_asdk_app…` ID; пакет и MCP-конфигурация подготовлены, установка в ChatGPT ещё не выполнена.
