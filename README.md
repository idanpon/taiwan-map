# Taiwan Field Notes

Личная карта поездки в Тайвань: GitHub Pages для интерфейса, собственный VPS для авторизации, каталога и пользовательских данных. Прежняя временная версия остаётся рабочей до проверки нового размещения.

## Размещение

Исходники: https://github.com/idanpon/taiwan-map. Интерфейс собирается и публикуется workflow из main. Публичный адрес API и режим входа хранятся в pages.config.json; Repository Variables могут их переопределить. Прежняя временная версия остаётся доступной до завершения переключения; VPS и DNS настраиваются отдельно.

[Порядок размещения](docs/DEPLOYMENT.md). Частная диагностика VPS и персональные экспорты не входят в публичный репозиторий.

## Схема размещения

| Компонент | Адрес |
|---|---|
| Интерфейс | `https://idanpon.github.io/taiwan-map/` |
| API | `https://taiwan-77-105-138-163.sslip.io` |
| API-процесс | `127.0.0.1:18080`, Node.js 24 + SQLite, systemd |

Для API можно использовать технический hostname с IP на sslip.io. DNS, маршрутизация nginx/Caddy и HTTPS health проверены на VPS 18.10.2026. Это зависимость от внешнего DNS-сервиса; при смене IP потребуется изменить адрес API. Домен знакомого не используется. Ранее добавленный маршрут `/taiwan/*` удалён из Caddy на VPS 18.10.2026; nginx оставлен без изменений.

В режиме `AUTH_MODE=bearer` API после проверки пароля выдаёт случайный токен на 14 дней, сервер хранит только SHA-256 токена. Клиент отправляет его в Authorization и использует `credentials: omit`. Cookie не выдаются и не принимаются в этом режиме. Поэтому сторонние cookie для работы входа не нужны. Точный CORS allowlist и проверка членства остаются обязательными.

Токен сохраняется в sessionStorage этой вкладки, переживает обновление страницы; обычно после закрытия вкладки нужен новый вход (восстановление вкладок браузером может восстановить sessionStorage). Пароль не сохраняется. Если sessionStorage недоступен, токен остаётся только в памяти. Сервер отзывает сессию при выходе и проверяет срок действия. Токены никогда не передаются в URL. Как любой токен в JS, он доступен скриптам того же origin: нужно доверять коду всех проектов на `idanpon.github.io`. Применяется CSP, пользовательский текст экранируется, сторонний JS не загружается.

Прежний `AUTH_MODE=cookie` сохранён как отдельный режим для будущего размещения на одном HTTPS site: HttpOnly, Secure, SameSite=Strict. Режимы не смешиваются. Схему БД при переключении менять не требуется.

## GitHub Pages

1. Pages → Source → GitHub Actions. В текущем варианте Custom domain оставить пустым.
2. Адрес проверенного API и режим bearer заданы в `pages.config.json`, customDomain пустой. Изменения адреса проходят через обычный commit. При необходимости Repository Variables `PAGES_API_BASE`, `PAGES_AUTH_MODE`, `PAGES_CUSTOM_DOMAIN` переопределяют эти значения; это публичные настройки, не секреты.
3. Запустить workflow вручную или отправить commit в main. Сборка тестирует код и публикует только `dist/`.

Если адрес API не задан ни в файле конфигурации, ни в переменных, сборка показывает «Сервер данных ещё не подключён» и блокирует форму. Относительные файлы и ES-модули работают в `/taiwan-map/` и в корне будущего custom domain. Статусы и заметки сохраняются через API в SQLite; sessionStorage содержит только токен авторизации. Экспорт JSON тоже требует авторизации.

Публичные HTML/JS доступны без пароля — это оболочка. Все персональные данные, статусы и заметки выдаёт защищённый API после входа. В `dist/` нет backend-кода, seed-каталога, БД, пароля или хеша. В исходниках репозитория находятся только стартовые 10 публичных туристических мест; персональные экспорты туда не добавлять.

## VPS

Основной вариант для имеющихся ресурсов — systemd, без Docker и отдельного БД-сервера. `server/taiwan-map.service`: отдельный пользователь, код `/opt/taiwan-map`, данные `/var/lib/taiwan-map`, память до 192 MiB, loopback:18080. Перед установкой подтвердить Node 24+ и его путь в ExecStart. Env хранить в `/etc/taiwan-map.env`, root:root, 0600; ключи — `.env.example`.

`APP_PASSWORD_HASH` создаётся `node server/password.mjs`, пароль подаётся через stdin. После создания `/etc/taiwan-map.env` скрипт `python3 server/configure-pages-env.py https://API-HOST` переключает настройки на GitHub Pages, сохраняя существующий хеш пароля и создавая частную резервную копию env. Он не меняет базу и не перезапускает службу. Затем нужно проверить proxy и перезапустить taiwan-map.

Параметры: `APP_ORIGIN=https://API-HOST`, `FRONTEND_ORIGIN=https://idanpon.github.io`, `AUTH_MODE=bearer`. Пока `TRUST_PROXY=0`: реальный IP в цепочке nginx TCP/SNI → Caddy не подтверждён. Тогда лимит входов общий для источника-прокси. Нельзя доверять произвольному X-Forwarded-For либо включать PROXY protocol сразу для всех upstream.

Нельзя заменять существующие nginx/Caddy-конфиги: nginx занимает 443, Caddy — 80 и внутренний 8444, работают xray и другие сервисы. Docker Compose и примеры отдельного API-поддомена оставлены как альтернативы, не как основной способ для этого VPS.

## Перенос текущих данных

На старой карте скачать Export JSON и сохранить вне репозитория, например `export.private.json`. При остановленном API и пустой целевой базе:

```sh
DATABASE_PATH=/var/lib/taiwan-map/taiwan.sqlite node server/import.mjs /private/export.private.json
```

Импорт транзакционный, не меняет непустую БД, сохраняет каталог, ссылки, кастомные статусы, заметки и версии. Пароли/сессии и полная старая история не входят в JSON-экспорт. Финальный экспорт делать перед переключением; изменения после него в импорт не попадут. Исходный сайт отключать только после проверки нового.

## Архитектура

12 таблиц: поездки, пользователи, членство, категории, места, ссылки, статусы, текущие состояния, история, сессии, ограничитель входа, метаданные. Пока один общий профиль; будущие аккаунты имеют собственные состояния через user/place. Справочник статусов расширяемый, текущий основной статус один. Изменение состояния атомарно пишет историю и проверяет версию; устаревший клиент получает 409. CORS не заменяет авторизацию: сессия и членство проверяются сервером.

Часы: timezone/weekday intervals/exceptions/note/label и дата проверки. Источники просмотрены 18.10.2026; праздничный график не подтверждён. Геопозиция по кнопке остаётся в браузере и требует HTTPS.

SQLite: foreign keys, WAL, busy timeout, SQL-миграции с проверкой неизменности. Ежедневный snapshot после появления каталога, включая первый успешный вход, хранение 14 дней в `backups/`. Внешнее копирование не настроено; копии на том же VPS не защищают от его потери.

## Файлы и проверки

- `public/`, `src/ui.mjs`: HTML/CSS/JS, Leaflet 1.9.4, OSM tiles с атрибуцией и обычным кешированием, без bulk/offline загрузок.
- `scripts/build-pages.mjs`: сборка без npm-зависимостей; runtime тоже не требует сторонних npm-пакетов.
- `src/core.mjs`, `server/`: API, SQLite, systemd, импорт, read-only диагностика.
- `drizzle/`: SQL-миграции; `db/schema.ts` — описание схемы. Для разработки новых миграций нужен Drizzle generator, но запуск и Pages от него не зависят.
- `.github/workflows/pages.yml`: тесты на push/PR, публикация из main.

`npm test` проверяет вход/выход, persistence, членство, конфликты, limiter, CORS/OPTIONS/ошибки/запрещённые origins, импорт/откат и Pages-сборку без backend-файлов. `npm run build:pages` собирает интерфейс. Независимый HTTPS hostname и запуск systemd проверены на VPS. Проверка входа, переноса данных и полного пользовательского сценария в браузере ещё требуется.
