# Taiwan Map — общий контекст для новых чатов

Актуализировано 24 октября 2026. Это входная точка для параллельной работы; подробные спецификации находятся в профильных документах. После бережного уплотнения календаря (PR #38) добавлены мобильное закрытие карточки свайпом вниз и ранняя фиксация направления свайпа календаря; детали — в `MAP_THEMES.md` и `PLANNING.md`. Перенос локальной папки и документация не меняют функции сайта или данные сервера.

## Проект и размещение

- Репозиторий: `idanpon/taiwan-map`, origin `https://github.com/idanpon/taiwan-map.git`.
- Локальная папка на текущем Mac: `~/Projects/taiwan-map`. Это обычный checkout со своей `.git`, не привязанный к управляемому worktree приложения.
- Интерфейс: `https://idanpon.github.io/taiwan-map/`; календарь — `planning.html`.
- API: адрес в `pages.config.json`, bearer-режим. На VPS код расположен отдельно в `/opt/taiwan-map`, данные — `/var/lib/taiwan-map`, env — `/etc/taiwan-map.env`.
- GitHub Actions проверяет PR и публикует Pages из main. Backend/systemd не обновляется этим workflow. Не переносить локальные пути на VPS и не менять инфраструктуру из-за организации папок на Mac.

## Принятые решения

### Доступ и данные

Без входа открывается публичная карта. Пользовательских заметок, скрытых мест, календаря и экспорта в анонимной проекции нет. Авторизованный viewer видит частные данные, но не может их менять. Editor может делать все действия продукта; admin дополнительно управляет аккаунтами. Основные сведения о местах по-прежнему обновляются через управляющий чат; сайт не получил публичный редактор названий/адресов/координат.

Общие заметки и статусы принадлежат поездке, а не отдельному пользователю. Не подменяй пользовательскую note подготовленным описанием. Краткое описание места — о самом месте; полезные факты — транспорт/нюансы/время визита; детали конкретного плана — в пользовательской заметке. Часы и даты проверяются по первоисточникам, не выдумываются.

Сессии сохраняются в localStorage с привязкой к API, выдаются на 180 дней и продлеваются при открытии сайта. Есть пароль, Telegram и passkeys. Пароль минимум 6 символов, подтверждение при создании/смене и переключаемая иконка глаза. Физическое поведение Face ID/Apple Passwords контролируется iOS; сайт биометрию не получает. Не трактуй продление сессии как повторную проверку личности.

### Карта

Прямой MapLibre GL JS 6.15.0, без Leaflet и связующего движка. Bright — светлая, Fiord — тёмная; готовые цвета подложки не перерабатываются. Темы интерфейса через общие CSS-переменные. Пользовательский выбор сохраняется, первоначально учитывается системная тема.

Fallback внутри того же MapLibre — обычные OSM raster tiles из локально заданного стиля. Это защита от устойчивого отказа поставщика, а не реакция на один тайл, offline или фон. Без постоянных проверок и скачивания областей. Атрибуция обязательна. При невозможности WebGL доступен список.

Исходная позиция показывает все места. При открытии карточки выбранное место за 300 мс центрируется в свободной части карты; при закрытии — в полной карте, без изменения масштаба и накопления сдвига. Учитывается reduced motion. Есть компас только при повёрнутой карте, геолокация, копирование названий/адреса, свёрнутые источники. На телефоне карточка закрывается свайпом вниз за шапку либо от начала содержимого; несохранённые правки защищены прежним подтверждением.

Ярлыки photoSpot / limitedDates / reservation независимы и видны рядом с названием, не на пинах. OR внутри ярлыков, AND между группами фильтров. Даты/свободное расписание необязательны и независимы. Расписание изначально свёрнуто; дата окончания включительна, сравнение по Asia/Taipei. Бронирование — необязательная HTTP/HTTPS-ссылка. Ничего не проставлять всем местам автоматически.

Скрытие убирает место из обычной карты и списка, восстановление возвращает. Удаление действительно удаляет backend-запись. Обе операции доступны editor/admin. Массовое «Удалить всё» в скрытых требует подтверждения количества. Выбор альтернатив календаря сам по себе не удаляет места.

### Планировщик

Поездка: 29 декабря 2026 — 9 января 2027, вылет 28 декабря. Фактические даты всегда перечитывать из API: пользователь может изменить их после этого handoff.

Месяц / неделя / день / список; понедельник первым. По умолчанию период текущего дня. Типы: задача, решение, маршрут/посещение. Даты без времени отличаются от точных моментов; отображение учитывает выбранный пояс устройства/события. «Сегодня» и идущий период одного цвета, близкий срок отдельный, просрочка заметнее. Записи без даты находятся в «Без срока».

Общие задачи, необязательный ответственный. Любой editor/admin фиксирует выбор после обсуждения. Альтернативы можно скрыть либо оставить. При пересечении нескольких решений вопросительный статус не снимается, пока другие условия не решены; предпросмотр поясняет связи. Ручная смена статуса места, участвующего в незакрытом решении, направляет в календарь вместо обхода решения.

Зависимости мягкие: предупреждают, но позволяют отметить выполнение. Автоматического каскадного пересчёта сроков на сайте нет. При переносе рейса/маршрута чат проверяет зависимости и предлагает изменения с предварительным просмотром. Внешние фиксированные даты не сдвигаются автоматически. Нет внешних напоминаний, ИИ или автопроверки расписаний внутри сайта.

Многодневные события объединены полосами по датам, длинные занимают верхние свободные дорожки. Месяц показывает три дорожки и «⋯ +N» для остальных записей; все доступны по дню. Неделя прокручивается внутри своего блока. Навигация — кнопки, клавиши и свайп с ранней фиксацией направления; горизонтальная прокрутка недели остаётся нативной.

### Последние изменения интерфейса

Загрузка центрирует логотип со вращающейся звездой, учитывает видимую высоту и safe area; переключателя темы на загрузке нет. Шапка единая у карты и календаря. В PR #38 снижены её высота и отступы, визуальные кнопки навигации/добавления — 36 px, режимы — 34 px, между рядами оставлены явные зазоры. Отображаемые значения фильтров 14 px поверх нативных 16 px controls; при вводе поиска показывается настоящий input. Значения синхронизируются после сброса и смены часового пояса.

## Проверки и публикация

Node.js 24+, `npm ci --ignore-scripts`, `npm test`, `npm run build:pages`. Правка сенсорных жестов прошла 151 тест, сборку и браузерные проверки касаний на 360/393 px, мыши/клавиатуры на 1440 px и уменьшения движения. Системный Safari на физическом iPhone этими проверками не заменяется. Это историческое свидетельство, не замена проверке новых изменений.

GitHub Pages строит только frontend. Не включай в PR базу, частный экспорт, server env, SSH-ключи, токены и `.local/`. Перед миграциями/массовой записью — согласованный backup. Версии ресурсов в Pages генерируются сборкой: не менять вручную URL и dist. При недоступном HTTPS git push используй доступный GitHub-коннектор; удалённое дерево должно совпадать с проверенным локальным деревом. Для созданного PR добавляй его в артефакты чата.

## Контекст параллельных чатов

Новый чат начинает с `AGENTS.md` и этого файла. Для задачи о сроках — дополнительно `PLANNING_OPERATIONS.md`; для входа — `PUBLIC_ACCESS_PASSKEYS.md`; для данных — актуальный API. Файлы проекта дают общий контекст, но не являются автоматической копией всей переписки. После изменения договорённостей обновляй handoff и профильную документацию. Параллельные изменения кода делай в отдельных ветках/worktree, не меняя branch под работающим соседним чатом.

## Локальный архив после переноса

`.local/outputs/` — скриншоты и результаты проверок; `.local/work-archive/` — прежние сценарии, частные снимки и импорты; `.local/visualizations/` — копии макетов; `.local/inputs/` — найденные исходные handoff/CSV/XLSX. Подробности машины — `.local/LOCAL_SETUP.md`, журнал переноса — `.local/migration-2026-10-24.json`.

Архив не является текущим состоянием сервера. Часть исторических сценариев использует старые абсолютные пути. Старый checkout-путь оставлен символической ссылкой на новую папку для совместимости текущего чата; исходные ссылки на отчёты/макеты тоже сохранены. Новую работу вести из корня проекта, не из архива. Ни архив, ни исходные личные файлы не публиковать.
