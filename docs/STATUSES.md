# Города и статусы

Фильтр городов строится из `places.city`, показывает число мест и сортируется
по названию. Для появления города достаточно добавить место с этим значением;
списка городов в HTML нет. Выпадающий список сохраняет компактность при росте
каталога и поддерживает клавиатуру и мобильные устройства.

Admin и editor открывают «Управление статусами» рядом с фильтром статусов.
Можно создавать статусы и менять название, цвет и символ любого существующего
статуса, включая встроенные. Viewer видит результат, но не может менять статусы.
Редактирование сохраняет ID: назначения мест, заметки и история не меняются.
Версия статуса предотвращает перезапись одновременных изменений.

Название — 1–40 символов после удаления пробелов по краям; цвет — `#RRGGBB`.
Символ — пустая строка либо один Unicode code point после NFC-нормализации:
буква, число, знак пунктуации или текстовый символ. Например, `! ? + ✓ ★ №`.
Исключены emoji/pictographic символы, флаги, пробелы, комбинируемые знаки,
служебные и невидимые символы, variation selectors и многосимвольные emoji.
Знак проверяется одинаково интерфейсом и API, выводится как текст и сохраняется
в экспорте. Контрастный чёрный или белый текст выбирается по цвету кружка.

Добавочная миграция `0002_status_symbols.sql` добавляет `symbol` и `version`.
Для существующих встроенных статусов и «Хайп!» она один раз сохраняет палитру,
ранее заданную только интерфейсом. После этого используются сохранённые цвет
и символ, без переопределения по ID или названию. Другие пользовательские цвета,
идентификаторы статусов и привязки мест сохраняются. Повторный запуск миграций
не меняет новые настройки.

При обновлении сначала сделать согласованный SQLite backup, проверить новую
версию на копии БД и обновить backend, затем публиковать Pages. Предыдущий
backend совместим с добавочными столбцами, но его интерфейс их не использует.
