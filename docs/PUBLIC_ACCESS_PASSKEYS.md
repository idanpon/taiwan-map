# Публичная карта и вход

## Уровни доступа

- Без входа: только нескрытые места, категории, текущие статусы, ярлыки, расписания, часы, адреса и публичные ссылки. Общие заметки, календарь, скрытые места, экспорт и управление недоступны.
- Просмотр: все данные карты и календаря, общие заметки, скрытые места и экспорт. Изменять данные поездки нельзя. Собственные способы входа по-прежнему управляются в профиле.
- Редактор: все действия продукта, включая календарь, ярлыки, статусы, заметки, скрытие, восстановление и удаление мест.
- Admin: права редактора плюс управление участниками.

`GET /api/public/data` строит отдельную проекцию с перечисленными столбцами. Он не обрезает `/api/data` или экспорт: новые частные поля не публикуются автоматически. В публичном ответе нет заметок, внутренних версий, дат поездки, имён участников, скрытых мест или календаря. Защита записи остаётся на backend, независимо от видимости кнопок. Анонимный интерфейс не запрашивает календарь. После входа и выхода остаются карта, фильтры и выбранная карточка. Просмотр скрытых мест разрешён viewer отдельным GET, операции записи защищены прежними правами.

Публичные данные доступны любому, в том числе без браузера. CORS ограничивает браузерные origin, а не делает эти данные конфиденциальными.

## Запоминание устройства

Bearer-токен сохраняется в localStorage под ключом, включающим API base. Старый токен из sessionStorage переносится при первом открытии; пароль и данные Face ID в хранилище не попадают. Если постоянное хранилище заблокировано, используется сессионное или память страницы.

Сессия выдаётся на 180 дней. `/api/auth/session/refresh` продлевает действующую сессию при открытии сайта; сервер каждый раз проверяет пользователя, членство и отключение. Продление не считается новой проверкой личности. Выход удаляет серверную сессию и токен, другие вкладки перечитывают сохранённый токен при запросе. Отключение, удаление пользователя и сброс пароля отзывают сессии. Браузер/ОС могут самостоятельно очистить хранилище раньше.

Форма использует username/current-password, стандартный submit, подсказки для менеджера паролей и ограниченную отправку после autofill. Полная заполненная видимая форма отправляется один раз для текущей пары значений; обычный ручной ввод автоматически не отправляется. Ошибка не вызывает бесконечного повтора. Стрелка остаётся доступна. Возврат из системного окна не перезагружает открытую форму входа. Реальное поведение Apple Passwords / сторонних менеджеров проверяется на iPhone; система управляет Face ID, сайт не получает биометрические данные.

## Passkeys

SimpleWebAuthn server 14.0.3 и browser 13.2.2 зафиксированы в package-lock; браузерный bundle и MIT license включены в сайт. Нет внешней runtime-загрузки зависимостей. WebAuthn JSON совместим между этими версиями; серверные тесты и браузерная проверка подписей проверяют реальную совместимость.

RP ID берётся из hostname FRONTEND_ORIGIN (при отсутствии — APP_ORIGIN), expected origin — точный origin. На текущем Pages это `idanpon.github.io` / `https://idanpon.github.io`. Вызовы API остаются на VPS; перенос API не меняет ключи. Перенос интерфейса на другой домен потребует заранее спланировать перенос ключей или добавить их заново после обычного входа. HTTPS обязателен, для локальной проверки поддерживается localhost.

Два шага регистрации: options после действующей сессии и проверки недавнего входа (10 минут), затем verify. Если вход был давно, интерфейс просит снова войти и повторить добавление в профиле. Ключи discoverable, userVerification required. Одна учётная запись может иметь до 20 ключей. Хранятся публичные ключи, счётчики и метаданные; приватный ключ и биометрия остаются в системном менеджере.

Вход не требует логина: options, системный выбор ключа, verify, обычная сессия приложения. Проверяются подпись, RP ID, origin, user handle, флаг проверки пользователя, счётчик и активное членство. Challenges одноразовые, живут 5 минут; регистрация привязана к текущей сессии. Replay/неверные данные не создают сессий. Регистрация и вход ограничены по частоте. Поддерживаются ES256 и RS256 без удалённой attestation/metadata-службы.

Удаление ключа в профиле удаляет его серверную привязку и сессии этого ключа на других устройствах; текущая сессия сохраняется. Отключение аккаунта сохраняет ключи, но блокирует вход. Сброс пароля администратором удаляет ключи участника для восстановления доступа, удаление аккаунта также очищает ключи. Собственная смена пароля сохраняет собственные ключи. Пароль и Telegram остаются запасными способами входа. ОС может запросить код устройства вместо Face ID.

## Развёртывание и проверки

До применения добавочной `0008_passkeys.sql` сделать согласованный SQLite backup и проверить миграцию на копии с сравнением всех прежних столбцов и строк. Установить зависимости через `npm ci --omit=dev --ignore-scripts`; env, proxy, systemd unit не меняются. Сначала backend с прежними закрытыми API и новым публичным API, затем Pages. Откат к предыдущему коду допускает добавленные столбцы; актуальную БД не заменять снимком при обычном откате кода.

Тесты покрывают недоступность закрытых данных без входа, явную публичную проекцию, viewer, сохранение и отзыв сессии, реальную криптографическую регистрацию и вход, недавнюю проверку личности, origin/RP, UV, user handle, подпись, счётчики и replay. Браузерная проверка использует виртуальный platform authenticator Chrome, новый browser context с прежним localStorage и мобильный viewport. Это не заменяет проверку физического Face ID и Apple Passwords на iPhone.
