# Устройство Taiwan Map

Состояние кода после аудита 6 ноября 2026. Приложение рассчитано на одну
общую поездку и небольшую группу. Мультитенантность, отдельный сервер очередей,
ORM и frontend-фреймворк не требуются.

## Границы системы

GitHub Pages отдаёт HTML, CSS, ES modules, локальные библиотеки, manifest и
push-worker. Две страницы — карта и `planning.html` — используют общие форму
входа, шапку, темы, профиль и справку. Сборка не содержит каталога, базы,
учётных данных или личных экспортов.

Node.js 24 на VPS обслуживает API. SQLite — единственное рабочее хранилище.
В этом же процессе работает очередь Web Push. `server/index.mjs` связывает
HTTP, конфигурацию, базу, статические страницы для локального запуска,
необязательные снимки и завершение службы. GitHub Actions VPS не обновляет.

## Данные и транзакции

Рабочая схема определяется последовательностью `drizzle/*.sql`. Название папки
историческое. Мигратор хранит SHA-256 каждого применённого файла в
`_app_migrations` и запрещает менять уже применённую миграцию. Новые изменения
схемы оформляются следующим SQL-файлом. Cloudflare D1, Drizzle runtime и
генератор не используются. Неполная старая TypeScript-схема и её metadata
удалены из рабочей ветки, история остаётся в Git.

- `trips`, `users`, `memberships`, `sessions` задают поездку и доступ.
- `places`, `categories`, `place_links` содержат сведения о местах.
- `statuses`, `user_place_states`, `state_events` сохраняют общие статусы,
  заметки, версии и историю. `trip-shared` — исторический владелец общего состояния.
- `planning_items`, варианты, связи, зависимости и события хранят общий план.
  Удаление места оставляет подпись связи и саму задачу.
- `trip_timezone_changes` задаёт точные моменты смены пояса. До первой смены
  действует Москва. Часы работы мест остаются местными для самого места.
- `planning_reminders`, `notification_preferences`, `push_devices`,
  `push_deliveries` содержат личные правила, устройства и очередь.

Синхронный `transaction(db, callback)` открывает `BEGIN IMMEDIATE`, а внутри
другой транзакции — savepoint. Callback не может быть async. HTTP body и
сетевые запросы читаются до начала транзакции. Пакетный импорт календаря
использует ту же службу записи и одну внешнюю транзакцию: ошибка последней
записи откатывает также ранние записи, статусы мест, связи и историю.

Сохранение карточки атомарно проверяет версии состояния и ярлыков. У видимости
и статусов собственные версии. Решения и смены поясов имеют предпросмотр с
хешем актуального снимка. Это проверка устаревшего состояния, не подпись и не
замена авторизации. Запись повторно проверяется внутри транзакции.

## Доступ и совместимость

Анонимный API перечисляет разрешённые поля явно. Он не формируется обрезанием
полного экспорта. Viewer читает частные данные и меняет только свои способы
входа/напоминания/устройства. Editor и admin меняют данные продукта; только
admin управляет участниками. `owner` сохраняется для начальной настройки
старой общей учётной записи, а не как новая продуктовая роль.

Bearer-сессии привязаны к API base, cookie-режим оставлен для совместимого
размещения. Сервер проверяет членство и отключение при каждом запросе.
Запоздалый отказ старой сессии не должен очищать более новую сессию клиента.
Пароль, Telegram и passkeys используют существующую выдачу сессий.

Старые API маршруты, формы ответов и версии экспорта сохранены. JSON-экспорт
не является полной резервной копией: он не содержит учётных данных, личных
правил напоминаний, устройств и очереди. Для восстановления всей системы
используется согласованный SQLite backup. Старый map-only importer отказывается
от экспорта с календарными записями или сменами пояса.

## Сборка и сопровождение

`build-pages.mjs` обнаруживает верхнеуровневые JS/CSS/manifest в `public/`,
вычисляет версию и обновляет импорты модулей. MapLibre проверяется по manifest,
SimpleWebAuthn bundle — по установленному закреплённому пакету. Выходной
каталог внутри репозитория допускается только `dist/`; исходники, `.local/`,
Git и родительские каталоги защищены от очистки, включая символьные ссылки.

Проверки — Node test runner, локальные временные SQLite и HTTP, сборка Pages.
Мок push-транспорта проверяет очередь, но не доставку на физический iPhone.
Нативные Safari/Face ID также требуют проверки на устройстве.

Результаты этого аудита, оставшиеся риски и план выпуска — в
[AUDIT_REFACTOR.md](AUDIT_REFACTOR.md). Публикация и резервные копии — в
[DEPLOYMENT.md](DEPLOYMENT.md).

## Почему сохраняем эту архитектуру

Для одной общей поездки и нескольких/десятков участников обычные ES modules
и один процесс Node/SQLite покрывают текущие сценарии без отдельной очереди,
ORM и frontend-фреймворка. Чистые правила делятся между клиентом и сервером,
а критические права и транзакции остаются на сервере. MapLibre используется
напрямую, резервная подложка работает в том же движке — подробности и причины
в [MAP_THEMES.md](MAP_THEMES.md).

Общий план и состояния мест отделены от личных способов входа, устройств
и напоминаний. Подготовленное описание и пользовательская заметка хранятся
раздельно. Политика качества карточек — [PLACE_IMPORT.md](PLACE_IMPORT.md).
Изменение реального маршрута через чат не является автоматическим пересчётом
внутри сайта — [PLANNING_OPERATIONS.md](PLANNING_OPERATIONS.md).

Этот документ описывает реализованную систему. Существенное новое решение
сначала фиксируется кратко в spec с причиной, после реализации — в документе
соответствующего модуля. Отдельный реестр ADR не нужен, пока он не приносит
практической пользы. Порядок — [AGENTS.md](../AGENTS.md), формат —
[specs/README.md](../specs/README.md).
