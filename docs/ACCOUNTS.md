# Учётные записи и права

Каждый участник имеет отдельную учётную запись и сессию. Карта общая:
статусы мест и заметки видны всем участникам поездки. Изменение сохраняет
реального автора в `state_events`; старые записи и их версии сохраняются.

| Роль | Карта и экспорт | Статусы и заметки, создание статусов | Пользователи и доступ |
|---|---|---|---|
| admin | Да | Да | Да |
| editor (редактирование) | Да | Да | Нет |
| viewer (просмотр) | Да | Нет | Нет |

Редактирование каталога мест пока не реализовано: эта версия добавляет
права к существующим операциям карты. Лимита в 5 участников нет; текущая
защита от неконтролируемого роста разрешает до 500 учётных записей, включая
отключённые. Это оставляет запас для группы из 20+ человек.

## Первый admin

1. Войти с нынешним общим паролем поездки.
2. Нажать «Настроить аккаунты».
3. Задать имя, личный логин (`idanpon` уже подставлен в форме) и новый
   пароль длиной от 6 символов и его повтор.

Настройка атомарно превращает прежнюю общую идентичность в первый admin,
сохраняет её ID и данные, отзывает прежние сессии и отключает вход по
общему паролю. Текущий браузер получает новую сессию. До этой настройки
старая авторизация продолжает работать, Telegram ещё не доступен.
После настройки `APP_PASSWORD_HASH` в env больше не используется для входа.
Его сохранение не является запасным входом.

## Создание и управление

Admin открывает «Пользователи» и создаёт отдельный аккаунт с именем,
логином, паролем (от 6 символов), повтором пароля и ролью. Логины нечувствительны к регистру, длина 3–40,
допустимы латинские буквы, цифры, `.`, `_`, `-`.

В карточке пользователя admin меняет имя, роль, логин, пароль или отключает
доступ. Сохранение отзывает сессии пользователя; изменение собственного
аккаунта потребует повторного входа. Отключение не удаляет историю. Последнего
активного admin нельзя отключить или понизить, в том числе при одновременных
запросах. Права повторно проверяются на сервере в каждом запросе.

## Telegram

Используется современная Telegram Login Library / OpenID Connect с
`response_type=post_message`, без Client Secret и без Bot Token.
Настройка в BotFather:

- выбрать бота → Login Widget → Switch to OpenID Connect Login;
- Trusted Origins: `https://idanpon.github.io` (добавленный интерфейсом
  корневой `/` не меняет origin);
- Signing Algorithm: RS256;
- указать публичный числовой Client ID в `/etc/taiwan-map.env`:
  `TELEGRAM_CLIENT_ID=8988860984` для `@TaiwanMapBot`.

Для popup-потока не нужен серверный callback / Client Secret. Запрашивается
только `profile`, без номера телефона и разрешения боту писать пользователю.
Бэкенд проверяет JWT библиотекой `jose`: подпись через официальный JWKS,
issuer, audience, время и одноразовый серверный nonce сроком 5 минут.
Одна идентичность Telegram может принадлежать только одному аккаунту.

Пользователь с аккаунтом по логину открывает «Профиль» / «Пользователи» →
«Привязать Telegram». Затем оба способа входа ведут в тот же аккаунт.
Если Telegram ещё не привязан, попытка входа создаёт только заявку.
Она не создаёт аккаунт или сессию и не открывает карту. Admin может
одобрить заявку, создав аккаунт с выбранной ролью, либо отклонить её.
Если аккаунт по логину уже существует, участнику следует войти в него
и привязать Telegram; это также уберёт его ожидающую заявку.

## Развёртывание и откат

Перед обновлением VPS сохранить согласованный полный SQLite backup через
SQLite backup API / `VACUUM INTO`, проверить `PRAGMA quick_check` на копии,
сохранить HEAD, env и установленный unit. Сырые копии только основного файла
активной WAL-базы недостаточны. Частные backup-файлы остаются вне git.

На VPS нужно установить runtime-зависимость (`npm ci --omit=dev
--ignore-scripts`) с Node из `/opt/taiwan-node`. Запуск следующей версии
применяет добавочную миграцию `0001_accounts.sql`; `0000` не меняется.
Установленный unit и proxy менять не нужно. Новый публичный Client ID
добавляется в env без вывода паролей или их хешей. После проверки сборки и
миграции на копии можно обновить checkout и перезапустить только taiwan-map.

Сначала обновить backend, проверить health и `/api/auth/config`, затем
публиковать Pages. До создания первого admin старый frontend остаётся
совместим. После создания admin старый frontend без поля логина больше
не подходит; нужно обновить страницу, чтобы загрузить новую версию.

Миграция добавочная. До настройки admin можно откатить код на предыдущий
HEAD: старый код игнорирует дополнительные столбцы и таблицы. После
настройки admin нельзя просто запускать прежнюю общую авторизацию:
это снова откроет доступ по прежнему общему паролю. Такой откат требует
осознанного решения и, при необходимости, восстановления проверенной
предварительной копии БД, с учётом последующих пользовательских изменений.

## Проверки

`npm ci --ignore-scripts`, `npm test`, `npm run build:pages`.
Тесты покрывают роли, сохранение старых данных, общие состояния и конфликты,
отзыв сессий, защиту последнего admin, Telegram-подпись и claims, nonce и
replay, одобрение заявок, привязку к существующему аккаунту, bearer и cookie.
Внешний вход настоящего Telegram-пользователя нужно проверить после
публикации с настроенным Trusted Origin.

Источники: [Telegram Login](https://core.telegram.org/bots/telegram-login),
[jose](https://github.com/panva/jose),
[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
Новые пароли: PBKDF2-HMAC-SHA256, 600000 итераций; прежний hash на
100000 итераций поддерживается для перехода с общего пароля.

Во всех полях пароля доступна кнопка с иконкой глаза: перечёркнутый глаз
означает, что пароль показан. При создании
аккаунта пароль вводится дважды; несовпадение отклоняется интерфейсом и API.
