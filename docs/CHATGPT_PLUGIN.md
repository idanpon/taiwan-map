# Наполнение через ChatGPT

Базовый плагин подключён к production. Первоначальный контракт описан в [спецификации](../specs/2026-11-08-chatgpt-plugin.md). Статус выпуска расширения — в [спецификации проживания и транспорта](../specs/2026-11-10-stay-transport-fixed-statuses.md).

## Как работает

ChatGPT читает актуальную карту и план, предлагает связанные изменения,
проверяет их и показывает предпросмотр. Пользователь подтверждает кнопкой
в карточке либо однозначным ответом на конкретное предложение. Изменение
пакета или поездки требует нового предпросмотра и подтверждения.

Например: новая публичная точка музея и частная задача «Проверить билеты»
связаны в одном предложении. Они сохранятся вместе; ошибка задачи откатит
также добавление музея. После потери ответа квитанция доступна из другого
подключённого чата или на `assistant.html?proposal=…`.

Неполный черновик сохраняется по просьбе пользователя и доступен только его
автору. Кнопка «Оставить черновиком» отменяет текущую готовность к применению.
Общие заметки не перезаписываются описаниями мест. Новые места публичны,
если не скрыты. План и заметки доступны участникам. Через `plan.delete`
можно удалить проживание или переезд. Удаление мест и управление пользователями доступны на сайте по правам.

В карточке виден точный дифф предложения, включая поля транспорта, роли
мест и снимаемые зависимости при удалении. В карточке можно изменить состав
пакета, название, даты без часов, статус места и видимость. Точные часы,
пояса и другие поля транспорта уточняются в чате.
Если карточка недоступна, инструменты остаются рабочими; `review_url` ведёт
на авторизованную страницу сайта с тем же предпросмотром.

## Компоненты и контракт

```text
ChatGPT + инструкция плагина
       │ OAuth / MCP / встроенная карточка
       ▼
Существующий Node API ── служба предложений ── SQLite
       ▲                       │
       │ сессия сайта           └─ существующая служба календаря
assistant.html
```

| Модуль | Ответственность |
|---|---|
| `src/assistant-schema.mjs` | Строгие структуры: неизвестные поля отклоняются |
| `src/assistant-changes.mjs` | Каталог, статусы/ярлыки/видимость и вызов существующих правил плана |
| `src/assistant-proposals.mjs` | Личные черновики, версии, предпросмотр, транзакция и квитанция |
| `src/assistant-tools.mjs` | Контракты инструментов, общие инструкции MCP и контекст поездки |
| `src/assistant-oauth.mjs` | OAuth 2.1 authorization code + PKCE S256, отдельные ограниченные токены |
| `src/assistant-http.mjs`, `src/assistant-mcp.mjs` | HTTP/CORS, OAuth discovery, MCP Streamable HTTP |
| `public/assistant-card.js`, `src/assistant-widget.mjs` | Общий интерфейс подтверждения и официальный MCP Apps bridge |
| `src/assistant-ui.mjs`, `public/assistant.js` | Вход через сессию сайта, согласие OAuth, предложения, отзыв доступа |
| `plugins/taiwan-map/` | Переносимый manifest, MCP-конфигурация и инструкция поведения |

Инструменты: `trip_read`, `proposal_list`, `proposal_read`, `proposal_save`,
`proposal_preview`, `proposal_apply`, `proposal_draft`, `proposal_cancel`.
Один пакет — до 30 операций и 120 КБ; HTTP MCP/tool — до 128 КБ. До 100
незавершённых предложений на автора. `trip_read` возвращает общую поездку,
включая скрытые места, но не пароли, сессии и личные уведомления.

Перед изменениями ассистент читает `trip_read`. Поле `planning_rules` содержит текст [единых правил](PLANNING_RULES.md),
а `planning_today` — текущую дату и действующий пояс поездки. Этот же файл
включается в инструкции при инициализации MCP и указан в `AGENTS.md` для
Codex. Описание `proposal_save` направляет к этому контексту.

Ассистент оценивает смысловые дубли, необходимость интервала и разумность
срока. Сервер проверяет структуру, версии и связи и продолжает принимать
просроченные записи и исторические даты.

`proposal_save` получает стабильный UUID предложения и ключ каждой операции.
Созданные записи получают стабильные серверные UUID. Ссылка `$ключ` внутри
пакета указывает на создаваемое место/задачу; операции идут в порядке
зависимостей. Повтор неизменного сохранения не повышает версию. Изменение
существующего предложения требует его актуальной версии.

`plan.create` и `plan.update` принимают все пять типов и используют
[контракт полей планировщика](PLANNING.md#проживание-и-транспорт).
`$ключ` можно использовать в `places[].place_id` для отеля или любой
точки переезда и в `dependencies`. `plan.update` проверяет версию записи,
включая преобразование старого `visit` на месте. `plan.delete` принимает
`id` и `version` проживания или переезда. Предпросмотр содержит удалённую
запись и изменившиеся зависимости. Для остальных типов сохраняются
существующие операции. `place.state` принимает только [фиксированные
статусы](STATUSES.md) или `null`.

Для места разделены `catalog_version`, `state_version`, `tags_version` и
`visibility_version`. Изменённые координаты требуют источника и описания
точности; структурированные часы — источника и даты проверки. Сервер
проверяет структуру и непротиворечивость, но не удостоверяет достоверность
содержимого сайта: источник должен проверить чат. VPS не скачивает
произвольные URL и не выполняет команды из них.

Предпросмотр выполняет реальные правила записи в SQLite savepoint и
откатывает всё, включая производные изменения решений и напоминаний.
Пользователь видит разницу до/после. Хеш общей поездки защищает от
параллельных изменений; это консервативная проверка — даже несвязанная
правка может потребовать обновить предпросмотр. Если изменилась версия
самой целевой записи, сначала нужно исправить предложение по свежим данным.

Применение требует ID/версии и `confirmation_token` точного предпросмотра.
Записи, история и квитанция `applied` фиксируются одной транзакцией.
Подтверждение в чате — правило поведения доверенного клиента: сервер может
проверить ревизию и токен, но не доказать, что человек действительно написал
«да». Для строгого подтверждения отдельным браузерным действием потребуется
другая политика; сейчас реализован согласованный вариант «кнопка или чат».

При потере ответа сначала читается `proposal_read`. Если результат сохранён,
возвращается та же квитанция. После временной ошибки допускаются три повтора
с теми же реквизитами. 400/403 исправляются, 401 требует входа, 409 — свежих
данных и подтверждения. Страница ограничивает ожидание запроса 20 секундами;
дальнейшая неизвестность прямо показывается пользователю. Фоновой работы
после закрытия чата нет.

## Model3: общий механизм изменений (локально)

После явного перехода поездки `trip_read` дополнительно возвращает
`planning_v3`: источники, версии, рабочие размещения, derived-проверки и
capabilities. Персональные напоминания, байты файлов и ключи хранения не
выдаются. Инструментов теперь десять: добавлены read-only `planning_contract`
(allowlist полей команд) и `planning_evaluate` (commands либо choices).
Viewer может сравнивать варианты без записи.

`proposal_save` принимает либо прежние `operations`, либо `planning_commands`,
от 1 до 100. Смесь запрещена: каталог и model3-маршрут согласуются отдельными
предложениями. Неизвестные команды и поля отвергает общий доменный валидатор.
Ссылки на создаваемые записи — `{command,entity}`, существующие — ID/версия.
`planning_evaluate` не является разрешением на запись.

Model3 proposal хранит `domain_changeset_id`. Preview возвращает человеческий
diff, конкретные причины и exact acknowledgement keys общего changeset.
Карточка блокирует применение при blocking issues и до отметки всех
подтверждений. Apply требует прежние version/token и явно согласованные keys.
Draft/cancel/edit инвалидируют общее подтверждение. После потерянного ответа
`proposal_read` и список восстанавливают applied из устойчивой общей квитанции,
включая случай применения через другой адаптер. Повтор не создаёт операцию.

Изменение working choice не отменяет бронь. Подготовка, сроки, переносы,
пересмотр и файлы подчиняются [единым правилам](PLANNING_RULES.md).
Автоматические зависимости и тексты причин строятся по связям и кодам общего
движка. AI не требуется для пересчёта после ручного изменения на сайте.
Эта версия не опубликована; прежняя production-интеграция не заменена.

## Доступ

Идентичность — аккаунт **карты**, а не ID аккаунта ChatGPT. Пользователь один
раз проходит вход на сайте и разрешает подключение. Пароль и passkey не
передаются модели. Первоначально `ASSISTANT_USER_IDS` содержит только ID
владельца; затем можно разрешить других участников, каждому своё подключение.
Viewer читает, editor/admin могут изменять поездку; роли проверяются при
каждом запросе, а автор черновика — при каждой операции с ним.

OAuth-код действует пять минут, используется один раз и привязан к PKCE,
клиенту, точному callback и ресурсу. Access token действует час, refresh —
30 дней, при обновлении оба заменяются. В SQLite сохраняются их хеши.
Scopes: `trip:read`, `trip:write`. Отзыв на `assistant.html`, отключение
участника и смена/сброс пароля прекращают доступ; изменение роли сразу
ограничивает операции. Обычный выход с сайта не отключает ChatGPT — для
этого есть отдельный отзыв.

MCP использует свои Bearer-токены. Браузерные операции требуют обычную
сессию сайта и разрешённый Origin. Общая политика существующего API не
ослабляется. DCR/CIMD, client secrets и публичная регистрация клиентов
не включены; используется предварительно заданный public client с PKCE.

## Публикация и личное подключение

При выпуске следовать [обычному порядку обновления backend](DEPLOYMENT.md).
При первом развёртывании плагина проверить миграцию `0010_chatgpt_plugin.sql`
на согласованной копии SQLite.
Встроенная карточка собирается esbuild при первом MCP-запросе и кешируется
в процессе; нужны все закреплённые production dependencies. `npm ci
--ignore-scripts` поддерживается, внешние CDN карточке не нужны.

Файл `docs/PLANNING_RULES.md` входит в поставку backend и читается при старте
Node. Для обновления правил выпустите backend с этим файлом и перезапустите
службу. При устаревших описаниях инструментов обновите метаданные
установленного MCP-подключения. `trip_read` возвращает актуальные правила
с сервера.

Настройки существующей службы:

| Переменная | Значение |
|---|---|
| `ASSISTANT_ENABLED` | `1` включает; по умолчанию маршруты закрыты (404) |
| `ASSISTANT_CLIENT_ID` | `taiwan-chatgpt` (совпадает с пакетом) |
| `ASSISTANT_USER_IDS` | JSON-массив разрешённых ID аккаунтов карты, сначала только владелец |
| `ASSISTANT_REDIRECT_URIS` | JSON-массив **точных HTTPS callback**, показанных конкретным подключением ChatGPT |
| `ASSISTANT_UI_URL` | `https://idanpon.github.io/taiwan-map/assistant.html` |

Для production обязательны HTTPS и существующие `APP_ORIGIN`,
`FRONTEND_ORIGIN`, `AUTH_MODE=bearer`. Callback нельзя угадывать или
заменять wildcard. В репозитории нет настоящих callback, токенов и ID
разрешённых участников. Пустые allowlist дают только публичные метаданные
подключения, но не позволяют вход или чтение поездки: так можно получить
точный callback при первоначальной настройке, не открывая доступ к данным.

Прокси должен передавать `/api/assistant/*`,
`/.well-known/oauth-authorization-server` и
`/.well-known/oauth-protected-resource/api/assistant/mcp` в существующий Node.
Нужно пропускать POST до 128 КБ и заголовок Authorization. Старый пример
nginx только с `/api/` и лимитом 8 КБ для этого не подходит; проверять текущий
proxy перед выпуском. Длинные SSE-соединения не нужны.

Затем выпустить Pages с `assistant.html`, создать личное MCP-подключение
в ChatGPT к `https://taiwan-77-105-138-163.sslip.io/api/assistant/mcp`, выбрать
OAuth с указанным client ID и без client secret. Добавить выданный callback
в серверный allowlist и завершить вход аккаунтом карты.

Пакет лежит в `plugins/taiwan-map`. Для интерфейса ChatGPT, требующего
зарегистрированное сопоставление MCP (`plugin_asdk_app…`), связать пакет
с ID созданного личного подключения; его нельзя заранее выдумать. Использовать
личный источник плагинов, без отправки в публичный каталог. Только после
установки проверить новую беседу: чтение → черновик → предпросмотр →
подтверждение → квитанция, затем продолжение из второго чата и отзыв доступа.
«Любой чат» означает чат, в котором установленный плагин доступен и включён;
пакет не может заставить неподдерживаемый режим ChatGPT вызвать инструмент.

Отдельные OpenAI API key, модель на VPS, API поисковика и Telegram не нужны:
рассуждение и доступный поиск выполняет ChatGPT. Доступность инструментов
зависит от конкретного режима и возможностей аккаунта; сервер не обещает
поиск там, где ChatGPT его не предоставляет.

Основа интеграции: [MCP](https://developers.openai.com/plugins/build/mcp-server),
[OAuth](https://developers.openai.com/plugins/build/auth),
[карточки MCP Apps](https://developers.openai.com/plugins/build/chatgpt-ui),
[пакет и личная установка](https://developers.openai.com/plugins/build/plugins).

## Проверки и ограничения

`tests/assistant.test.mjs` проверяет атомарность предпросмотра/применения,
ошибку последней операции, идемпотентность, конфликты, заметки, решения,
изоляцию черновиков, роли, scope, PKCE, одноразовость/истечение кода,
ротацию/отзыв токенов и полный сценарий через официальный MCP-клиент.
Миграционные тесты проверяют сохранение прежних данных и новые значения
по умолчанию. Проверки Pages/HTTP включают новую страницу.

Локальный браузерный smoke test выполнен на тестовой базе: 375/1280 px,
обе темы, длинные строки, вход, правка даты, новый предпросмотр, конфликт,
сохранение и квитанция после reload. Карточка проверена через официальный
AppBridge: initialize → tool-result → tools/call → сообщение о сохранении.
OAuth callback в этой проверке перехвачен локально; реальные аккаунты
ChatGPT не затронуты. Проверка в настоящем ChatGPT остаётся после публикации.

Полный backup — SQLite. JSON-экспорт поездки не включает личные предложения,
историю плагина и OAuth-подключения. При восстановлении старой базы
предыдущие подтверждения не следует считать действительными: отозвать
подключения и подготовить новые предложения. При откате релиза можно
отключить `ASSISTANT_ENABLED`; обратной SQL-миграции нет.
